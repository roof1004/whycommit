# 기록 초안: 오늘 한 작업, 남은 작업

퀴즈 결과는 이미 노트에 저장돼 있다. 여기서는 PR 본문이나 커밋 본문에 들어갈 기록을 만든다. 기록은 자동으로 초안을 만들어도 되지만 항상 확인을 받는다.

## 작성 스타일

`env`의 `config.hasWritingStyle`이 true면 `wc.mjs config get --out "<tmpDir>/config.json"`을 실행하고, 그 파일의 `writingStyle`을 읽어 그대로 따른다.

## 오늘 한 작업

- `changes.json`의 커밋과 변경 내용을 기준으로 쓴다. 현재 대화에서 드러난 작업 의도를 보탠다.
- 관련 있는 것끼리 묶어서 짧은 항목으로 쓴다. 변경에 없는 일은 지어내지 않는다.
- PR 모드이고 이미 PR이 있으면, 먼저 `wc.mjs pr status --out-current "<tmpDir>/current.md"`를 실행한다. 지금 PR의 whycommit 부분 "오늘 한 작업"을 출발점으로 삼고, 새 커밋의 내용을 더한다. 사용자가 GitHub에서 고친 줄은 지우지 않는다.

## 남은 작업

아래 다섯 출처에서만, 이 순서로 모은다. 항목마다 출처를 붙인다. 출처를 다른 것으로 바꿔 붙이지 않는다. 코드를 읽다가 에이전트가 발견했지만 확인 질문으로 묻지 않은 문제는 넣지 않는다.

1. **기획 문서와 구현의 차이** (`source: "plan"`)
   - `wc.mjs plan-doc find`를 실행한다.
     - `remembered.path`가 있고 `rememberedExists`가 true면 그 문서를 읽는다.
     - `remembered`가 `{"path": null}`이면 사용자가 "없다"고 한 것이니 묻지 않고 넘어간다.
     - 기억된 것이 없으면 `candidates`에서 기획 문서로 보이는 것을 읽는다. README가 기획 문서인 경우도 있다.
   - 후보가 없거나 기획 문서인지 확실하지 않으면 한 번만 묻는다.

     ```
     기획 문서가 있나요? 남은 작업을 찾는 데 써요.
     1. 경로 알려 주기
     2. 없음
     ```

     답을 `wc.mjs state set-plan-doc --path <경로>` 또는 `--none`으로 기억시킨다. 다음부터는 묻지 않는다.
   - 기획 문서에 있는데 아직 구현되지 않았거나, 구현이 기획과 다른 것 중 이번 작업과 관련된 것을 적는다.
2. **현재 대화에서 미루기로 한 것** (`source: "conversation"`): "나중에", "일단 빼고"처럼 미룬 것
3. **변경된 파일의 TODO 주석** (`source: "todo"`, `ref: "경로:줄"`): `changes.json`의 `todos`
4. **열려 있는 관련 이슈** (`source: "issue"`, `ref: "#번호"`): `gh` 준비가 됐을 때만 `wc.mjs gh issues --out "<tmpDir>/issues.json"`을 실행하고, 이번 작업과 관련된 것만 고른다.
5. **확인 질문으로 확인된 문제** (`source: "quiz"`): 퀴즈의 확인 질문을 거쳐 문제로 확인된 것. 사용자가 문제가 아니라고 제대로 설명했으면 넣지 않는다.

같은 일이 여러 출처에 있으면 한 번만 적고, 더 앞선 출처를 붙인다.

## 초안 보여 주기

번호는 두 목록을 이어서 붙인다. 그래야 "2번 빼줘"가 헷갈리지 않는다.

```
기록 초안이에요.

오늘 한 작업
1. 401 응답을 받으면 토큰을 갱신하고 다시 요청
2. 동시에 온 401에서 갱신이 한 번만 일어나게 처리

남은 작업
3. 갱신에 실패하면 로그아웃 (기획 문서)
4. 재시도 횟수 제한 (TODO 주석: src/auth/session.js:12)

고칠 곳이 있으면 말해 주세요. 괜찮으면 "응"이라고 해 주세요.
- 말로 고치기: "2번 빼줘", "더 짧게"
- 다시: 방향을 알려 주면 새로 써요
- 직접 쓸게: 직접 입력해요
- 비우기: 한 항목(오늘 한 작업 또는 남은 작업)을 통째로 빼요
```

`config.body.includeLearning`이 true이거나 사용자가 이번에 학습 내용도 넣어 달라고 하면, 미리보기 끝에 "이해한 내용 / 이해하지 못한 내용 주제도 함께 들어가요"라고 알린다. 그 주제는 노트에서 가져오므로 초안에 따로 쓰지 않는다.

## 고치기

사용자가 "응"이라고 할 때까지 반복한다.

- **말로 고치기**: 요청대로 고치고 다시 보여 준다.
- **다시**: 방향을 받아 새로 만든다. "직접 쓸게"로 쓴 뒤에 "다시"라고 하면 자동 초안으로 돌아간다.
- **비우기**: 그 항목을 뺀다. 둘 다 비우면 기록할 것이 없으니 7단계를 건너뛸지 묻는다.
- **직접 쓸게**:
  1. 어느 항목인지 묻는다. "1. 오늘 한 작업 2. 남은 작업 3. 둘 다"
  2. 사용자의 입력을 받는다. 둘 다면 하나씩 받는다.
  3. 받은 글을 `<tmpDir>/manual-done.txt`나 `<tmpDir>/manual-todo.txt`에 그대로 쓰고, `wc.mjs draft split --file <그 파일> --out <tmpDir>/manual-done.json`으로 항목을 나눈다. 줄바꿈과 쉼표로 나뉜다.
  4. 나온 항목은 문장을 고치지 않는다. 사실 확인도 하지 않는다. 남은 작업에 쓰면 `source`는 `"user"`다.
  5. 다시 미리보기를 보여 준다.

## "앞으로도 이렇게 써줘"

사용자가 이렇게 말할 때만 작성 스타일을 저장한다. 직접 썼다는 이유만으로 저장하지 않는다.

1. 지금 초안에서 드러난 스타일을 몇 줄로 정리한다. 길이, 말투, 묶는 기준, 끝맺음 등.
2. 정리한 내용을 보여 주고 `<tmpDir>/style.txt`에 쓴 뒤, `wc.mjs config set-style --file <그 파일>`로 저장한다.
3. "다음 기록부터 이 스타일로 쓸게요"라고 알린다.

## 본문 만들기

확인이 끝나면 `<tmpDir>/draft.json`을 쓰고(`formats.md`) 본문을 만든다.

- PR 모드, PR 본문만: `wc.mjs body render --file "<tmpDir>/draft.json" --target pr --out "<tmpDir>/section.md"`
- 마무리 모드: `wc.mjs body render --file "<tmpDir>/draft.json" --target commit --out "<tmpDir>/body.txt"`

학습 내용을 넣을 때:
- `learning.include`를 true로 둔다. 설정이 켜져 있으면 생략해도 된다.
- PR 모드는 이 브랜치의 노트 전체를 쓴다 (`learning.branch`를 생략하면 현재 브랜치).
- 마무리 모드는 이번 퀴즈에서 저장한 `ids`를 `learning.ids`로 넘긴다.
